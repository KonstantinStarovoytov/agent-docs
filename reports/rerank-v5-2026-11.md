# Rerank 5 Fast instead of Rerank 4 Fast (experiment 28)

2026-11-16. `rerank-v4.0-fast` against `rerank-v5.0-fast` on the production
index (`agent_docs_hybrid_v1`), the same candidates for both models, and the
score thresholds measured again for v5.

**Verdict: switch.** Ranking is the same or better once label gaps are
counted. Answer quality is the same or better. Refusals are cleaner. Rerank 5
is billed per token ($0.02 per 1M) instead of per search (about $2 per 1,000),
which at 10 chunks a call is about 10-30x cheaper (an estimate from chunk
sizes, not from a bill). The catch: Rerank 5 scores are calibrated
probabilities, much lower than Rerank 4's, so all three score thresholds had
to change with the model.

## Setup

- Both models ranked the same pools. The query rewrites were frozen in
  `EVAL_CACHE_DIR` by the first (v4) run, and Cohere scores do not depend on
  the other documents in a call (reports/retrieval-diagnostics-2026-10.md).
- Primary trial key only. About 190 Cohere calls in total, 0 for the judge
  runs, which reused the cached scores.
- Langfuse runs carry the suffixes `-v4fast-2026-11-16`, `-v5fast-2026-11-16`
  and `-v5fast-floor010-2026-11-16`.
- Raw scores of every candidate, both models, with labels:
  [rerank-v5-2026-11-scores.json](rerank-v5-2026-11-scores.json), from
  `evals/experiments/rerank_model_scores.py`.

## Retrieval

`evals.run_experiments --skip-no-rerank` (10 candidates, rerank top 10) and
`evals.run_evidence_coverage_experiment --baseline-only` (no score floor).

| Dataset | Metric | v4.0-fast | v5.0-fast |
|---|---|---|---|
| retrieval-v3 (47) | hit@1 | 0.787 | 0.745 |
| | hit@5 / hit@10 | 0.979 / 0.979 | 0.979 / 0.979 |
| | nDCG@10 | 0.836 | 0.841 |
| | P@5 / P@8 | 0.545 / 0.473 | 0.553 / 0.484 |
| full-corpus-v1 (20) | hit@1 / hit@5 | 0.950 / 1.000 | 0.950 / 1.000 |
| | nDCG@10 | 0.907 | 0.893 |
| | P@5 | 0.610 | 0.540 |
| evidence-coverage-v1 (16) | coverage / complete | 0.573 / 0.250 | 0.625 / 0.312 |

Two drops pass the 0.03 gate line. Read case by case, both are mostly label
artefacts:

- **retrieval-v3 hit@1.** v5 loses 8 questions and wins 6.
  - In 4 of the 8 losses v5's first result answers the question, but the
    labels miss it: "package skills, hooks and subagents together" → Glossary ›
    Plugin; "repository-wide instructions to Codex" → Customization › AGENTS
    Guidance; "What file defines a skill" → Glossary › Skill (a tie at 0.915
    under v4); "What is SKILL.md" → the Codex skills overview.
  - 4 are real. Two of them put the Agent SDK page above the Claude Code page
    (OAuth: `agent-sdk/mcp.md`; subagents: `agent-sdk/subagents.md`); two put
    a nearby, weaker page first.
  - All 6 wins are real: v4 had put another product's page or an enterprise
    page first (Personalize ChatGPT for a Codex question, Agent Security and
    LLM Safety for Cursor questions).
- **full-corpus P@5.** The labels count every chunk of the right page. v5
  ranks the unrelated sections of that page lower: Cargo and NuGet for an npm
  question, "Installer variables" for a `CODEX_HOME` question. `search_docs`
  shows one passage per page, so this does not reach agents. The one
  full-corpus hit@1 v5 loses (Bash timeout) puts `tools-reference › Timeout
  and output limits` first, which is the right section; the labels name two
  others.

## Scores and thresholds

v5 scores are far lower and better separated. On a tiny probe the same
relevant document scored 0.88 (v4) and 0.73 (v5), an unrelated one 0.17 and
0.01.

| | v4.0-fast | v5.0-fast |
|---|---|---|
| Lowest best score of an answerable question (83) | 0.745 | 0.375 |
| Weakest correct chunk | 0.368 | 0.088 |
| Median correct chunk | 0.863 | 0.693 |
| Best scores of the 12 unanswerable questions | 0.109-0.898 | 0.001-0.767 |

Thresholds on these scores. Answerable = retrieval-v3, full-corpus-v1 and
evidence-coverage-v1; unanswerable = negative-v1.

| Best-score gate | answerable refused | unanswerable refused |
|---|---|---|
| v4 at 0.55 (old default) | 0 / 83 | 8 / 12 |
| v5 at 0.55 (old default kept) | 4 / 83 | 11 / 12 |
| v5 at 0.30 (**new default**) | 0 / 83 | 9 / 12 |
| v5 at 0.35 | 0 / 83 | 10 / 12 |

0.35 refuses one more unanswerable question, but the lowest answerable best
score is 0.375, only 0.025 above it. The six lowest answerable best scores
all belong to multi-part questions: v5 scores lower when no single chunk
answers the whole question. 0.30 keeps a margin of 0.075. Unanswerable
questions v5 still lets through: JetBrains AI Assistant (0.319), GitHub
Copilot instructions (0.384), the Claude Messages API (0.767; v4 0.898).

| Floor (`MIN_RERANK_SCORE`), v5 | evidence groups kept | correct chunks below it |
|---|---|---|
| 0.05 | 24 / 24 | 0 / 369 |
| 0.10 (**new default**) | 24 / 24 | 2 / 369 |
| 0.20 | 24 / 24 | 13 / 369 |
| 0.35 (old default kept) | 23 / 24 | 39 / 369 |

`other_sections`: on v4, the 0.35 cut passed 100% of correct and 98.7% of
incorrect candidates, so it filtered almost nothing. On v5, 0.10 passes 99.5%
and 96.3%, the closest match to today's behaviour. The cut is now a setting
(`OTHER_SECTIONS_MIN_SCORE`). A stricter cut (0.20-0.25) needs its own run
of experiment 25 with section labels.

The thresholds were chosen on the same questions they are reported on; there
is no holdout set.

## Answers (LLM judge)

`evals.run_answer_quality_experiment` with and without `--negative`,
`GENERATION_TOP_K=8`, judge `gpt-6-sol`. Each model ran with its own floor
(v4 0.35, v5 0.10). The runner does not apply the best-score gate; its effect
is in the table above.

| evidence-coverage-v1 (16) | v4.0-fast | v5.0-fast |
|---|---|---|
| faithfulness | 0.982 | 0.986 |
| citation correctness | 0.973 | 0.983 |
| answer relevance | 0.844 | 0.887 |
| context utilization | 0.639 | 0.670 |
| evidence coverage / complete | 0.719 / 0.500 | 0.719 / 0.500 |

| negative-v1 (12) | v4.0-fast | v5.0-fast |
|---|---|---|
| correct refusals | 1.000 | 1.000 |
| faithfulness | 0.975 | 0.971 |
| citation correctness | 0.954 | 0.983 |
| answer relevance | 0.375 | 0.329 |

On negative-v1 the right answer is a refusal, which the judge rates as
irrelevant, so answer relevance there is not a quality signal. The gate
metric for this set, correct refusals, is 1.000 for both. With the 0.30 gate,
9 of the 12 skip the answer model entirely (8 with v4 at 0.55).

On the `/ask` path the coverage gain from the retrieval table disappears:
both models cover 0.719 once the floor and the 8-chunk selection run.

## Rolling back

Every value is an environment variable:

```bash
COHERE_RERANK_MODEL=rerank-v4.0-fast
MIN_RERANK_SCORE=0.35
MIN_TOP_RERANK_SCORE=0.55
OTHER_SECTIONS_MIN_SCORE=0.35
```
